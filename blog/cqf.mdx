Cyclic Queuing and Forwarding ([CQF](https://1.ieee802.org/tsn/802-1qch/)) makes [latency](https://en.wikipedia.org/wiki/Latency_(engineering)) independent of the other traffic. A frame advances exactly one hop per cycle, so its delay depends only on the path length. No new hardware is needed: CQF is a particular way of configuring two [TSN](https://1.ieee802.org/tsn/) tools that already exist.

## 1. Definition

**Cyclic Queuing and Forwarding**, [IEEE 802.1Qch](https://1.ieee802.org/tsn/802-1qch/) (Annex T of [IEEE 802.1Q](https://standards.ieee.org/ieee/802.1Q/10323/)), divides time into cycles of equal length $T$, synchronised across the network. Two queues serve one traffic class and swap roles every cycle:

- during a cycle, frames **received** by a [bridge](https://en.wikipedia.org/wiki/Network_bridge) are stored in one queue;
- the frames received in the **previous** cycle are sent from the other queue.

A frame received in one cycle is therefore sent in the next [2][3].

## 2. How it is built from gates

<SourceFigure
  id="grigorjew2026-fig12"
  caption="Figure 3. CQF as a joint configuration of PSFP and TAS, one time slot: in each switch, PSFP assigns arriving frames to queue 7 while TAS transmits from queue 6."
/>

Standardisation-wise, CQF is not a separate shaper. It is a joint configuration of [Per-Stream Filtering and Policing](/blog/per-stream-filtering-and-policing) and the [Time-Aware Shaper](/blog/time-aware-shaper) [4]:

1. The **stream gate** of [PSFP](https://1.ieee802.org/tsn/802-1qci/) sets the internal priority value (IPV) of arriving frames, alternating between two values each slot, for example 7 and 6.
2. The **transmission gates** of [TAS](https://standards.ieee.org/ieee/802.1Qbv/6068/) run out of phase: while arriving frames go to queue 7, gate 7 is closed and gate 6 is open, and vice versa.

When bridge A opens a gate and sends, bridge B classifies those frames into its own closed queue. That queue opens exactly $T$ later. Both gating mechanisms need synchronised time, and every device carries the same configuration [4].

## 3. The cycle-time condition

CQF works only if every frame sent in a cycle reaches the next bridge and is queued before that cycle ends. The cycle must therefore cover:

- the transmission time of all frames the bridge may send in one cycle, which is what [admission control](https://en.wikipedia.org/wiki/Admission_control) limits;
- the propagation delay of the link;
- the processing delay of the receiving bridge;
- the synchronisation error between the two bridges.

The tutorial on decentralised latency models expresses this as a latency threshold per hop, $\Delta \le T - d_{\text{misc}}$. Here $d_{\text{misc}}$ accounts for synchronisation inaccuracy. If admission control keeps the worst-case delay of the hop below $\Delta$, the queue is guaranteed to be empty at the end of its cycle. The downstream shaper then sees every frame as eligible exactly $T$ after the upstream one [4].

End to end, the latency is about $T$ per hop. It varies by at most about one cycle, depending on where in a cycle the frame first arrives. This is why CQF gives very low [jitter](https://en.wikipedia.org/wiki/Packet_delay_variation) and why its bound needs no knowledge of the other flows [2].

## 4. Costs and comparison

The same tutorial evaluates CQF against strict priority, [ATS](https://1.ieee802.org/tsn/802-1qcr/) and CBS, using latency models that every bridge can compute locally [4]:

- **Half the traffic classes.** Each class needs two queues, so with eight queues only four classes remain for reserved traffic. Priorities are merged, for example 7 and 6 into 7, which increases interference within a class.
- **Best jitter under a global configuration.** When one setting is applied network-wide, CQF minimised jitter.
- **Beaten by per-hop tuning.** When latency thresholds could be optimised hop by hop, strict priority with a [network calculus](https://en.wikipedia.org/wiki/Network_calculus) bound gave better latency and jitter than CQF.
- **A cycle is a hard minimum.** Even a lightly loaded path pays $T$ per hop, so $T$ trades bandwidth per cycle against latency.

For network calculus, CQF is the simplest case of all. Each hop is a delay element of $T$ with no burst growth. The burstiness cascade that complicates [aggregate multiplexing](/blog/aggregate-multiplexing-residual-service) does not occur.

## 5. Summary

| Property | Cyclic Queuing and Forwarding |
| --- | --- |
| Standard | IEEE 802.1Qch, Annex T of IEEE 802.1Q |
| Built from | Stream gates (802.1Qci) and transmission gates (802.1Qbv) |
| Queues per class | Two, alternating every cycle |
| Needs time synchronisation | Yes |
| Latency | About one cycle $T$ per hop |
| Main cost | Half the traffic classes; a full cycle per hop even at low load |
