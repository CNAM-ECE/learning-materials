[RSTP](/blog/rstp-rapid-spanning-tree) builds one tree for the whole network, so every redundant link stays idle. Once a network carries several VLANs, there is an obvious improvement: give different VLANs different trees, so that each link carries some traffic. That is what the Multiple Spanning Tree Protocol (MSTP) does.

## 1. Definition

The **Multiple Spanning Tree Protocol** was defined in IEEE 802.1s-2002 and merged into IEEE 802.1Q-2005. It is an extension of RSTP that makes VLANs more useful [1]. Under MSTP, a spanning tree can be defined for individual VLANs or for groups of VLANs [1]. In the words of the IEEE 802.1 tutorial, different VLANs may share different spanning trees [3].

## 2. Regions and instances

MSTP organises bridges and VLANs in two steps [1]:

1. bridges are assigned to an **MST region**;
2. VLANs are mapped to **MST instances (MSTIs)**, each of which is a spanning tree.

Inside a region, frames of a VLAN follow the tree of the instance their VLAN is mapped to. The terms in the standard are as follows [1]:

| Term | Meaning |
| --- | --- |
| Multiple spanning tree (MST) | A spanning tree to which one or more VLANs are mapped |
| MST instance (MSTI) | A group of VLANs and the spanning tree they use inside a region |
| Common spanning tree (CST) | The tree that connects regions and single bridges; backward compatible with STP and RSTP |
| Internal spanning tree (IST) | The instance of the common tree inside a region |
| Boundary port | A port at the edge of a region, towards an RSTP or STP bridge or an end station |

## 3. One BPDU for all instances

Proprietary per-VLAN spanning trees send one set of BPDUs per VLAN. MSTP instead puts all of its information into **one BPDU format** [1]:

- the BPDU starts with a standard RSTP BPDU;
- an additional region section follows, with one message per MSTI (from 0 to 64 instances, although many bridges support fewer);
- instead of the full table of VLAN-to-instance mappings, the BPDU carries an **MD5 digest** of it. Two neighbours with the same digest and the same configured region values belong to the same region.

This keeps the number of BPDUs low. Because an RSTP bridge can read an MSTP BPDU as an RSTP BPDU, it also keeps compatibility with RSTP and with STP [1].

## 4. A region seen from outside

To RSTP bridges outside, a whole MST region looks like **one RSTP bridge**, however many bridges it contains. MSTP uses a remaining-hops counter inside the region instead of the message age timer of RSTP. The message age is incremented only once when spanning-tree information enters a region, so RSTP bridges see the region as a single hop [1]. As in RSTP, boundary ports facing end stations can be edge ports and start forwarding at once [1].

## 5. MSTP among the control options

<SourceFigure
  id="intro2017-control-plane"
  caption="Figure 3. Control options per VLAN: spanning-tree VLANs controlled by MSTP, shortest-path VLANs by IS-IS (SPB), and software-defined VLANs by an external agent, all in one network."
/>

802.1Q assigns a **control mode per VLAN**. Spanning-tree VLANs are controlled by MSTP, shortest-path VLANs by IS-IS, and software-defined VLANs by an external agent, and the modes can coexist in one network [2]. A TSN network can therefore keep MSTP for its ordinary VLANs while a controller installs explicit paths for streams, with [path control](/blog/ieee-802-1qca-path-control) or a CNC.

For determinism, MSTP shares the properties of RSTP. Each VLAN has one active path between two bridges, and that path changes when the tree of its instance reconverges.
