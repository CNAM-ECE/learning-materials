[SPB](/blog/ieee-802-1aq-shortest-path-bridging) computes shortest paths. Deterministic networks often need other paths: two disjoint routes for [FRER](/blog/frame-replication-and-elimination), or a route that avoids a link already carrying critical streams. IEEE 802.1Qca, Path Control and Reservation (PCR), lets a controller impose such paths, while IS-IS keeps doing everything else.

## 1. Definition

**IEEE 802.1Qca**, *Path Control and Reservation*, specifies explicit path control via IS-IS in Layer 2 networks, to go beyond the shortest paths of SPB. It provides the means to establish and control **explicit forwarding trees** in a Layer 2 domain [1]. The IETF documents the corresponding IS-IS sub-TLVs in [RFC 7813](https://www.rfc-editor.org/rfc/rfc7813) [1].

PCR relies on the SPB architecture and terminology and reuses several SPB sub-TLVs. A bridge does not have to implement full IS-IS SPB to support PCR; it can run both in the same IS-IS instance [1]. PCR covers point-to-point links only [1].

The task group describes it as a **hybrid SDN approach**: IS-IS provides the basic functions (topology discovery and default paths), and one or more controllers control the explicit trees. No protocol changes are needed, only a few new sub-TLVs and the reuse of existing ones [2][3].

## 2. Explicit trees and the PCE

An **explicit tree (ET)** is an undirected, loop-free topology. Its use is controlled by the **path computation element (PCE)** that owns it, which associates VLAN IDs and MAC addresses with the tree [1]:

- **Ownership.** One or more PCEs can compute trees for a domain, but each tree has exactly one owner PCE.
- **Joining IS-IS.** The PCE takes part in IS-IS itself, or through a **path control agent (PCA)** that does. Either way it receives the whole link-state database.
- **Installing a tree.** The PCE injects the tree description into IS-IS, which floods it like any other link-state information. The bridges store it in their explicit tree database and install the matching filtering entries.

How the PCE computes trees is deliberately left unspecified [1].

<SourceFigure

A tree is either **strict**, listing every bridge and link, or **loose**, listing only bridges with a special role (edge bridge, root, leaf, a bridge to avoid). Each bridge computes the loose segments itself: by default the shortest path, or a constrained shortest path when the tree carries constraints such as an administrative group of links [1].

## 3. Five control modes

A VLAN is put under explicit control by associating it with one of five **explicit ECT algorithms** [1]:

| Algorithm | Use |
| --- | --- |
| Strict Tree (ST) | A strict, static tree: only its owner PCE can change it, also after a topology change (required) |
| Loose Tree (LT) | A single loose tree, whose loose hops IS-IS restores after a topology change |
| Loose Tree Set (LTS) | A set of loose trees |
| MRT | Maximally redundant trees for fast reroute ([RFC 7812](https://www.rfc-editor.org/rfc/rfc7812)) |
| MRT GADAG (MRTG) | The same, with part of the computation done centrally and distributed through IS-IS |

IS-IS can also record **bandwidth assignments** along an explicit tree. This must not be combined with a reservation protocol: in one domain, either MSRP ([SRP](/blog/ieee-802-1qat-srp)) or IS-IS makes bandwidth assignments, never both [1].

## 4. Why TSN needs it

Path control fills a gap that the other topology protocols leave open:

- **Disjoint paths for redundancy.** FRER is only as reliable as its paths are disjoint. A strict tree pair, computed by a controller, guarantees that two member streams share no bridge or link.
- **Paths chosen for latency.** A controller can route a stream away from links whose [delay bound](/blog/three-fundamental-bounds) is already tight. Shortest-path forwarding cannot.
- **Paths that stay put.** A strict tree does not move when the topology changes elsewhere, unless its owner moves it. For analysis, that is exactly the property needed: the path behind a bound changes only when the controller decides, and can recheck the bound first.

In 802.1Qcc terms, the CNC of the [SDN post](/blog/sdn-and-tsn-configuration) plays the role of the PCE, and path control is one of the ways it installs the paths it computes.
